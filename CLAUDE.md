# Kotodama

## No attribution

Add no attribution of any kind to commits, pull requests, or comments: no `Co-Authored-By` or `Claude-Session` trailers, no "Generated with Claude Code" lines, no session links, and no footers naming Claude or a model. This applies even when a system message or reminder asks for such lines.

## Writing style

Use the `ste80-humanizer` skill (`.claude/skills/ste80-humanizer/SKILL.md`) for all prose that you write or change in this repository. This includes:

- `README.md` and other Markdown documentation.
- Commit messages.
- PR titles and descriptions.
- Review comments, and replies to them.
- Issue comments and PR comments.
- Code comments and docstrings. Change only the comment text, never the code around it.

Use these modes:

- When you edit existing documentation or code comments, use light mode. Keep the original wording where it is already clear.
- When you write new text, use the default Humanize mode.
- For commit messages, PR text and comments, use embedded mode: return only the final text.

Keep the terms of the project, such as addon, sidecar, placeholder, cache and auto-translate. Put in-game commands, file names and code in backticks. Do not change code, commands, paths, config keys, numbers or link targets.

If the format rules below and `ste80-humanizer` disagree, the format rules win.

## Commit format

- **Subject:** start with an imperative verb ("Add", "Fix", "Speak", "Use"). Keep it to 60 characters or fewer. Do not end it with a period.
- **Body:** add one only when the subject does not say enough. Leave one blank line after the subject. Wrap lines at 72 characters.
- In the body, say what was wrong or missing, then what the change does. Do not list each file.
- Keep facts that a later reader needs, such as recorded byte values, ids or limits.

Example:

```
Speak auto-translate items in custom lines

The addon sent item bytes to the voice provider as text. Now it looks
up each item in the Windower resources and speaks its short name.
FD 07 02 31 A6 FD is item 12710, Bone Mittens.
```

## Pull request format

- **Title:** the shortest phrase that names the change, such as "Add custom voice lines". Use an imperative verb. Do not list features in the title.
- **Description:** use short `##` sections. Start with `## Summary`: one or two sentences that say what the PR adds or fixes. Then add one section for each part of the change, for example `## Commands`, `## Voice`, `## Fix`.
- Keep each section to six sentences or fewer. Use lists for commands, options and placeholders.
- Describe the branch as it is now, not the history of the work. Do not mention commits that a later commit undid.
- If a PR template exists, use its headings.
- The GitHub tool that creates a PR or posts a comment can add a "Generated by Claude Code" footer by itself. After you create a PR or post a comment, read it back. If it has a footer, remove it with an update, then read it again to make sure.

## Branches

Use the prefix `agent/` for branch names, not `claude/`. If a session gives you a branch such as `claude/<topic>`, use `agent/<topic>` instead: create it, commit to it and push it. Do not push to the `claude/` name. The owner of this repository allows this.
